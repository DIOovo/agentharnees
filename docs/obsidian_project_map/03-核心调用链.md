# 核心调用链

关联：[[02-整体架构图]] · [[04-核心模块拆解]] · [[07-API接口地图]]

## 1. 应用启动与路由装配

起点是 Uvicorn 导入 `app.main:app`。`main.py` 导入数据库和两个 Router，在导入期建表，随后挂载路由。

```mermaid
sequenceDiagram
    participant U as Uvicorn
    participant M as app/main.py
    participant D as app/database.py
    participant DB as SQLite
    participant T as tasks.router
    participant R as runs.router
    U->>M: import app.main:app
    M->>D: import Base, engine
    M->>DB: Base.metadata.create_all()
    M->>M: FastAPI(...)
    M->>T: include_router()
    M->>R: include_router()
    M-->>U: ASGI app
```

最终结果：FastAPI 应用暴露根路径、Task 和 Run 共 9 个接口。

## 2. 创建任务

起点：`POST /tasks`。请求体先按 `TaskCreate` 校验，随后 `create_task()` 构造 `Task`，提交并刷新。

```mermaid
sequenceDiagram
    participant C as Client
    participant P as Pydantic
    participant API as tasks.create_task
    participant S as SQLAlchemy Session
    participant DB as SQLite
    C->>P: title, description
    P->>API: TaskCreate
    API->>S: add(Task status=pending)
    S->>DB: INSERT + COMMIT
    API->>S: refresh(Task)
    API-->>C: TaskRead
```

最终结果：新增一条 `tasks` 记录，返回 `TaskRead`。

## 3. 启动一次任务执行

起点：`POST /tasks/{task_id}/runs`。`start_task_run()` 查询任务后进入 `run_task()`，创建 Run，再按 `RUNNER_MODE` 选择路径。

```mermaid
flowchart TD
    A["POST /tasks/{task_id}/runs"] --> B["查询 Task"]
    B -->|不存在| C["404 Task not found"]
    B -->|存在| D["run_task"]
    D --> E["create_run<br/>Run=running, Task=running"]
    E --> F{"RUNNER_MODE"}
    F -->|llm| G["run_task_with_llm"]
    F -->|tool_agent| H["run_task_with_tool_agent"]
    F -->|其他/默认| I["run_task_with_fake"]
    G --> J["finish_run_success"]
    H --> J
    I --> J
    G -. "异常" .-> K["finish_run_failure"]
    H -. "异常" .-> K
    I -. "异常" .-> K
    J --> L["返回 RunRead"]
    K --> L
```

最终结果：正常或业务异常都会返回 `Run`；状态分别为 `success` 或 `failed`。

## 4. Tool Agent 多步执行

`run_tool_agent()` 生成提示词，最多循环 5 次。模型结果经 JSON 清洗和归一化后，要么保存 final step，要么调用工具并把结果追加到下一轮上下文。

```mermaid
sequenceDiagram
    participant R as runner_service
    participant A as agent_loop_service
    participant L as LLMClient
    participant X as LLM API
    participant T as Tool Registry
    participant W as workspace
    participant DB as SQLite
    R->>A: run_tool_agent(task, run)
    loop 最多 5 步
      A->>L: chat(system, conversation_context)
      L->>X: chat.completions.create
      X-->>L: message.content
      L-->>A: JSON 文本
      A->>A: parse_model_json + normalize_agent_output
      alt type = tool_call
        A->>T: run_tool(name, args)
        T->>W: list/read/tree
        W-->>T: 文件结果
        T-->>A: tool_result
        A->>DB: INSERT RunStep(tool_call)
        A->>A: 结果追加至上下文
      else type = final
        A->>DB: INSERT RunStep(final)
        A-->>R: answer
      else 解析或类型错误
        A->>DB: INSERT failed RunStep
        A-->>R: raise
      end
    end
```

最终结果：最终答案写入 `runs.result`；每次工具调用或错误写入 `run_steps`。

## 5. 查询执行轨迹

起点分别是 `/runs`、`/runs/{id}`、`/runs/{id}/logs`、`/runs/{id}/steps`。这些路由直接查询数据库，不经过 Service。

```mermaid
flowchart LR
    Client --> RunsRouter["runs router"]
    RunsRouter --> Check["按 run_id 检查 Run"]
    Check -->|不存在| NotFound["404"]
    Check -->|存在| Query{"查询类型"}
    Query --> Run["Run / RunRead"]
    Query --> Logs["RunLog[] / RunLogRead[]"]
    Query --> Steps["RunStep[] / RunStepRead[]"]
    Run --> Client
    Logs --> Client
    Steps --> Client
```
